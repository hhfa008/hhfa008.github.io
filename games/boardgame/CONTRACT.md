# 桌游板块 · 多人协作约定

三个会话（`d686a4ca` / `ea1bac15` / `50bdc849`）同时做这一件事，规则如下，违者回滚。

## 1. 谁都能改，但要会解冲突（2026-11-10 放宽）

不再限定目录所有权，也不再要求登记锁。谁都可以改任何文件，但必须遵守：

- **改之前先 `git merge` 把 main 合进自己分支**（不要 rebase），不要把陈旧副本当基线
- **冲突靠对比解决**：两边的实现都看一遍，取更好的那份，或者把两边合并；不许直接 `--force` 覆盖别人
- 解决冲突的那次提交要写清「冲突文件 + 采纳了谁的哪部分」
- 大幅重写别人的文件前，先在群里说一句你要改什么，避免两个人同时推同一块
- 合并后跑测试，红的不许进 main

## 2. Git 规则

- 每人一条分支：`boardgame/<自己的 sid 前 8 位>`，**禁止直接推 main**
- 每完成一个小步骤就 commit（哪怕只加了一个文件），提交信息写清做了什么
- 每 30 分钟至少 push 一次到 `~/games.git`
- 合并顺序：谁先完成谁先在群里说一声，由主会话（或第一个完成者）统一合进 main
- 冲突处理：先 `git merge main` 到自己的分支，解不了就停手报告，**禁止强推、禁止 rebase**

## 3. 备份

**不做备份**（磁盘紧张，git 提交本身就是版本记录）。不要生成 tar 包、不要建 `~/games-backups`。

## 4. 开工前 / 收工前（每个会话）

开工：
```bash
cd ~/games && git pull
export PATH=$HOME/.local/node/bin:$PATH
cat games/boardgame/LOCK.md 2>/dev/null   # 看别人在改什么
```

收工：
```bash
git add -A && git commit -m "<做了什么>"
git push ~/games.git HEAD:refs/heads/boardgame/<sid8>
```

## 5. 交流

- 进度、冲突、卡点直接在这条对话线程里说（agentbus 会把消息投到对应会话）
- 不要静默改别人的文件；不确定就先问

## 6. 合并（谁合、什么时候合、怎么合）

- **合并人**：每个合并窗口由 B（页面）会话担任；B 不在线时由主会话代合。合并人同一时间只能有一个。
- **合并窗口**：每 30 分钟一次，或在某个模块完成时提前一次。
- **合并流程**（合并人执行，顺序不能乱）：
  1. 拉全部分支：`git fetch ~/games.git '+refs/heads/*:refs/remotes/mac2/*'`
  2. 逐个 `git merge` 进 main（**不要 rebase**），冲突由**该分支的作者**解决，合并人不替人改代码
  3. 在合并候选上跑测试与构建（`npm test` / 构建冒烟），**红就不合**
  4. 通过后 `git merge --no-ff` 进 main，写清合并了哪几个分支
  5. 在三个会话的线程里广播合并结果：合了谁、测试输出、commit hash
- **禁止**：强推（`--force`）、跳过测试合并、合并人自己改别人的冲突代码、多人同时合并。

## 7. 提交节奏

- 小步提交：每完成一个可运行的小单元就 commit，不要攒一大坨
- 提交信息格式：`boardgame(<模块>): <做了什么>`，例如 `boardgame(data): 补 12 条德式样例`
- 每天至少 8 次提交、4 次 push；合并人负责统计并在窗口里报数

## 8. 安静工作（2026-11-10 用户要求）

- **不要再往群里发巡检、催办、角色提醒**；除了「卡点」和「完成」，不要主动汇报
- 需要别人配合时发一条足够具体的消息即可，不要反复追问
- 不做互相限制：谁的代码都可以改，冲突靠 merge + 对比解决
