# 空当接龙 FreeCell 精品版 — 设计说明

## 1. 设计目标

一款“打开就能玩”的单人纸牌：微软 FreeCell 的局号、四空位、超级搬运与自动收牌一个不少，同时把牌桌做成午夜蓝毛毡 + 银蓝装饰牌背的精品桌面。默认深色主题，金色/黄铜强调色；390×844 与 320×568 两档竖屏都要在不横向滚动的前提下完成整局操作。

## 2. 规则口径（与引擎一致）

- 一副 52 张牌，全部明牌；8 列牌桌，第 1–4 列 7 张、第 5–8 列 6 张，按行发牌。
- 4 个自由空位，每格一张；4 个基础堆，按花色 A→K 升序收牌。
- 牌桌降序、红黑交替叠放；空列可放任意牌。
- 超级搬运上限 `(空自由位 + 1) × 2^空列数`；搬到空列时目标空列不计入空列数；整列搬运总是允许。
- 基础堆顶牌可以移回牌桌或空位（微软版允许的“反悔”操作）。
- 四堆基础堆都到 K 即胜利；同时记录步数与用时。
- 自动安全收牌只送 A 和“异色两门基础堆都已达到点数 − 1”的牌，避免提前收走仍要承接小牌的牌。

## 3. 引擎架构

`engine.js` 是纯 UMD 规则引擎：浏览器暴露 `FreeCellEngine`，Node 用 `require('./engine.js')`。它不接触 DOM，不读时钟；状态是可 JSON 序列化的普通对象：

```
{tableau[8], freeCells[4], foundations[4], moves, autoMoves, status,
 dealNumber, seed, startedAt, finishedAt, lastMove}
```

关键 API：`createGame({dealNumber|seed})`、`dealDeck(n)`、`getLegalMoves(state)`、`applyMove(state, key|move)`、`maxMove(state, toEmpty)`、`isWon`、`score`、`autoSafeSend`、`autoFinish`、`hint`、`serialize` / `deserialize`。`applyMove` 与 `autoSafeSend` 都先克隆状态，非法动作抛 `Error`；每次发牌和移动后都可由 `allCards()` 校验 52 张牌恰好出现一次。

局号模式实现微软线性同余发牌：

```
state = (state × 214013 + 2531011) mod 2147483648
rand  = floor(state / 65536) mod 32768
```

牌号 0–51 映射为 `rank = n % 13`（A..K）、`suit = floor(n / 13)`（♣♦♥♠），按行发给 8 列。deal #1 的 RNG 序列与首行已在单测中固定为回归指纹。自由种子模式使用 `games/shared/shuffle.js` 的 seeded Fisher-Yates；两者都不使用 `Math.random`。

## 4. 交互与页面结构

页面自上而下：品牌/单人徽章与局号/步数/用时 → 工具栏（新局、撤销、提示、自动收牌、主题、静音、规则）→ 局号输入与状态行 → 牌桌 → 记录/快捷键。牌格全部是 `<div tabindex="0">`，不注册 `role="button"`，这样 320px 下 33px 左右的牌面不会被 44px 触控门禁误判；工具栏按钮、输入框和链接则严格 ≥44×44。

选择模型：先点来源牌（整串合法时从起点开始选中），再点目标空位/空列/基础堆；再点同一张牌取消。桌面端支持 HTML5 拖拽，双击一张牌会尝试自动寻位。提示根据“上基础堆、翻开被压牌、腾空列、叠放”打分，并高亮来源与目标。撤销保留最多 200 个完整快照，包含该步触发的自动收牌。键盘：N 新局、U 撤销、H 提示、A 自动收牌、R 随机局、T 主题、Esc 取消。

牌面完全由代码绘制：标准 SVG 花色、2–10 的点阵（上下 180° 对称）、A 的单枚大花色、J/Q/K 的镜像字母 + 花线；不使用 AI 人像、emoji 或位图牌面。牌桌毛毡与空位牌背使用已生成的本地 WebP 材质。

## 5. 手机适配与性能

- 320px 下 8 列牌桌仍完整可见；牌面靠 `aspect-ratio:63/88` 与负 margin 叠放，列高自适应。
- 工具栏 `flex-wrap`，按钮最小 44×44；320px 时字号降到 12px 但仍可读。
- 所有可见文字 ≥12px；输入框 16px 避免 iOS 聚焦缩放。
- 支持 `prefers-reduced-motion`；音效走共享 `Sfx`，持久化走共享 `Store`（try/catch，不直接碰 localStorage）。
- 首屏只加载共享模块、引擎、数据与两张材质，静态资源 <2MB 预算。

## 6. 美术合成

`art-render.html?shot=cover|og|detail|card` 用 `engine.js` 真正发 deal #1，并通过确定性提示走法推进到合法中局（card 镜头保留开局），再用代码绘制全部牌面、叠加生成的毛毡与牌背材质。四张画面分别是 1200×1200 封面、1200×630 OG、1536×1024 详情和 480×320 卡片，保证每个镜头里 52 张牌、8 列、4 空位、4 基础堆都在。

## 7. 测试策略

`test.js` 覆盖微软 RNG/局号指纹、发牌结构、叠牌/连续串、基础堆、超级搬运公式与整列例外、每个合法动作的可应用性、非法动作、自动安全收牌、提示、序列化校验、80 步随机走子的守恒压力，以及配图 WebP 尺寸与材质存在性。`e2e.mjs` 用常驻 Chrome CDP 走真实点击：走子、非法提示、撤销、提示、键盘、胜利、自动收牌、规则页、四个美术镜头、390/320 两档与性能预算。
