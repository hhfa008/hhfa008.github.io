01 · Scoring

判分只有三种

没有 LLM 当裁判，没有印象分，也没有“写得不错”的模糊评价。标准答案在开跑之前就固定，模型只需要交出可被程序检查的答案。

EXACT

精确匹配

合法着法集合、规则判定、布尔答案。集合必须完全相等，错一个元素就是错，不给部分分。

NUMERIC

数值判定

分数、子数、概率等数值答案。落在预先写死的容差内才算通过，四舍五入由引擎统一处理。

WIN RATE

胜率统计

B 组对局由内置引擎裁决胜负，汇总成胜率与 95% 置信区间。模型自己的复盘不算数。

一句话：不是让 AI 评判 AI，而是先把答案算死，再看 AI 答不答得上来。

02 · Task groups

三个题组，考三种能力

默认规模以 tasks.js 的实际清单为准；下表是完整清单的估计，示例命令用 --n 20 抽小样，模型延迟另算。

A

规则复现

精确匹配
考什么
给规则文本和局面，写出合法着法集合、终局判定或计分结果。覆盖马腿、塞象眼、炮翻山、飞将、吃过路兵、王车易位条件这类边角条款。
为什么难
规则能背，边角条件不能靠语感。漏掉一个附加条件，整题就是错的；长链推理还会把前面的正确判断带偏。
怎么判分
精确匹配。着法集合必须与引擎结果完全相等，布尔判定必须唯一；没有部分分，也不接受“思路正确”。
题量
约 40 题（棋类与牌类规则混合，以 tasks.js 为准）。
需要多久
10–15 分钟，另加模型响应延迟。
B

对局

胜率统计
考什么
与内置的确定性 AI 实际对局，棋类与牌类各若干局，按胜负结果统计胜率。
为什么难
要长程规划，也要在不完整信息下做决策；落子或出牌一旦发出就不能撤回，不能中途改规则。
怎么判分
胜率统计，附 95% 置信区间。胜负由对局引擎裁决，不采信模型自述或复盘。
题量
约 60 局（不同对手、先后手与开局分布）。
需要多久
20–30 分钟，取决于每步的模型延迟。

注意：内置 AI 不是人类高手。赢下它只说明赢了这个内置对手，不代表通用棋力。

C

代码任务

通过率
考什么
给函数签名和一组测试，模型提交代码，在沙箱里执行测试并统计通过情况。
为什么难
要一次处理对边界输入，错误没有人工找补；测试可见不代表能过，隐藏用例只看结果。
怎么判分
通过率。按测试用例的通过比例计分，逐题统计后汇总；执行环境和超时由执行者负责。
题量
约 12 题（含边界值、异常输入与性能约束）。
需要多久
30–45 分钟，含代码生成、执行和必要的重试。

04 · How to run

怎么参加

1

拿到仓库。克隆公开仓库并进入目录，不需要额外安装服务。

2

配好三个环境变量。key 只放在当前进程的环境里，不写进任何文件。

3

跑一轮，留下结果。先缩小规模确认链路，再跑完整题组。

  • AI_EVAL_API_KEY你的模型网关 key。只从环境变量读取。
  • AI_EVAL_BASE_URLOpenAI 兼容的接口地址，配合 --adapter http 使用。
  • AI_EVAL_MODEL模型标识，原样写进结果与榜单。
# 在仓库根目录执行；完整题组，固定 seed 42
AI_EVAL_API_KEY=... AI_EVAL_BASE_URL=... AI_EVAL_MODEL=... \
  node games/ai-eval/runner.js --all --seed 42 --adapter http --n 20
# 先小跑一轮，确认 key、地址和适配器能通
AI_EVAL_API_KEY=... AI_EVAL_BASE_URL=... AI_EVAL_MODEL=... \
  node games/ai-eval/runner.js --all --seed 42 --adapter http --n 5
凭据边界：key 只从环境变量读，不会上传到本仓库，也不会写进榜单；仓库里没有任何凭据。请不要提交 .env、带 key 的命令历史或包含密钥的日志。
05 · Submit

怎么提交成绩

一次提交需要三样材料。缺任何一样，都只能算“跑过”，不能上可复现榜。

  1. 结果 JSON。runner 跑完输出的原始结果，不要只截一张分数图。
  2. 复现命令。完整的命令，包含 --adapter、--seed 和 --n。
  3. seed。与结果文件一致；同一个 seed 应该能跑出同一套题。
// 榜单条目按这个形状记录
{
  "model": "your-model-name",
  "submitter": "一句话自述",
  "groupA": 0.85,
  "groupB": { "winRate": 0.6, "games": 60 },
  "groupC": 0.75,
  "seed": 42,
  "date": "2026-11-10",
  "resultsFile": "results/your-model-seed42.json"
}
提交渠道待定，见 games/ai-eval/TASKS.json。 渠道确定前，请不要把成绩发到公开 issue 里刷榜；我们只做格式校验（字段齐、类型对、日期与 seed 在），不保证分数真实。
06 · Honesty

诚实声明（不可省略）

  1. 成绩自报，没有第三方复核。我们只校验格式，不验证模型是否真的跑过，也不保证分数真实。拿榜单做采购或上线依据之前，请自己复跑一遍。
  2. 公开仓库藏不住题。题目、答案生成器和对局引擎都在明处；题量大只意味着覆盖广，不等于防作弊。
  3. B 组的棋力上限受内置 AI 限制。打败我们，只说明它赢了这个内置对手，不代表模型强，也不代表通用能力强。
  4. C 组的沙箱隔离由执行者负责。同一段代码在不同机器、不同超时和不同依赖下可能得到不同结果；我们不为执行环境背书。

这份榜单是公开实验记录，不是认证证书。分数旁边永远带着 seed、日期和“是否有结果文件”，请连同这些条件一起读。
