Free sample — 5 checks from the iOS Performance Audit Checklist

One check from each section of the full audit, reproduced here with the same wording. Each one gives you what to measure, the exact procedure, and the pass bar — enough to run it on your next build before you decide whether the other 55 checks are worth it.

  1. 01 Launch Check 1 of 60

    Measure cold, warm, and hot launch as separate numbers

    What to check
    The app reports three distinct launch durations instead of one blended average.
    How to test
    Cold launch = process not in memory (force-quit, then launch). Warm launch = process still resident. Use XCTApplicationLaunchMetric in a UI test and check Xcode Organizer › Launch Time and MetricKit MXAppLaunchMetric.
    Pass criteria
    Cold and warm are reported separately; cold launch p50 and p95 are both tracked per app version.
  2. 02 Memory Check 13 of 60

    Measure peak and steady-state memory on a physical device

    What to check
    Peak footprint and steady-state footprint for a realistic session.
    How to test
    Use the Xcode memory report, the Allocations instrument (All Heap & Anonymous VM), and MetricKit MXMemoryMetric peak memory. Exercise a full session: launch, browse, open detail, return, background, foreground.
    Pass criteria
    Peak ≤ 200 MB on the oldest supported device for a typical session, and steady state returns within 10% of the pre-session value.
  3. 03 Scrolling Check 26 of 60

    Track animation hitches during scrolling

    What to check
    Hitch time and hitch ratio while scrolling the heaviest list.
    How to test
    Use Instruments › Animation Hitches and MetricKit MXAnimationMetric. Measure a 30-second automated scroll on the densest screen.
    Pass criteria
    Hitch time ratio below 5 ms per second of scrolling; no single hitch longer than 100 ms.
  4. 04 Package size Check 37 of 60

    Measure the thinned App Store download size

    What to check
    The size users actually download, not the size of the .app on disk or the universal archive.
    How to test
    Export an App Store build (Organizer › Distribute App › App Store Connect › Export) and open the generated App Thinning Size Report. Compare the per-device variant sizes.
    Pass criteria
    Thinned download size is within the product budget on the primary device family; the audit records the exact report values.
  5. 05 Stability Check 49 of 60

    Establish a crash-free session baseline

    What to check
    Crash-free sessions and crash-free users are tracked per version, with a release threshold.
    How to test
    Read App Store Connect › Metrics or your crash backend; segment by app version, device, and iOS version.
    Pass criteria
    Crash-free sessions ≥ 99.5% on the current release (set and document a stricter target for critical apps); no single crash signature above 0.5% of sessions.
MEASUREMENT RULE

Never accept a simulator number for launch time, memory footprint, or hitch rate. The simulator has no jetsam limits, no thermal throttling, and different CPU characteristics.
