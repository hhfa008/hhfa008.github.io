Standing rule Official document first. Wire report second. Aggregation is a map to the original, never the citation. If I cannot reach the first, the piece says so.

01

The evidence ladder

Five tiers, one definition each. The tier is shown at the claim, not buried in a footer.

  1. A

    Official primary document

    A document published by the organisation making the claim: newsroom post, filing, standards document, model card, pricing page. I read the page itself, not a press summary of it.

    Marked “Tier A”
  2. B

    Primary media reporting, not repetition

    A named reporter at an outlet that did the reporting, with a byline, direct quotes or original observation. Still a second-hand account: treated as a report, not as proof.

    Marked “Tier B”
  3. C

    Secondary / aggregated a rewrite

    A rewrite of someone else’s reporting, a roundup with no named author, or a summary that does not link the source. Used to find the original; never used as the citation.

    Marked “Tier C”
  4. D

    Self-reported the vendor’s own number

    Benchmarks, usage figures, capacity and reliability claims published by the company about its own product. Labelled at the claim itself. Vendor-reported is not a synonym for false; it is not independent.

    Marked “Tier D”
  5. E

    Unverified / rumour a question, not a fact

    Single-source leaks, screenshots, “people familiar with the matter”. Written as an open question with the claim attributed. Never stated in the headline as if it happened.

    Marked “Tier E”

When credible sources disagree

Print both. Never average.

If two credible sources give different numbers, I do not split the difference or pick the friendlier one. I print both, with each date and definition, then add one line on what would settle it: a filing, a later document, or a direct measurement. If nothing settles it yet, the label is open — not a midpoint dressed up as a fact.

A benchmark split is a data point about the benchmark, not just about the model. Who ran it, on which version, with which prompt and decoding settings.

03

Correction log

Public, dated, and kept. A correction that only lives in a diff is not a correction.

Entry 01 · 25 October 2026

We said Chinese was not mentioned. The table said zh-TW.

What we published
On 24 October, a short note on Siri’s new languages said the rollout named five languages and did not mention Chinese. That was accurate about the prose we read, and wrong as a description of the release.
What we missed
Re-reading the same official release, the language table lists Traditional Chinese (zh-TW) as a supported locale for the new Siri. The prose named five languages; the table listed more. We had quoted the sentence and skipped the table beside it.
What changed
We appended this note to the item and rewrote the sentence to: “Five languages are named in the prose; Traditional Chinese (zh-TW) appears in the locale table.” The original sentence stays visible above the note. The headline was not changed, because the headline did not make the claim.
What is still open
The release does not say whether Simplified Chinese (zh-CN) is in the first wave. A table entry for zh-TW is not an answer to that, and we are not treating it as one.

What I changed in my process: check the document’s tables and locale lists before writing a sentence about what a release “does not mention”. Absence is a claim, and it needs the same reading as presence.

04

How I verify

Eight checks, each one an action rather than a principle. The full page has the working version.

  1. 01

    Read two official pages line by line — the announcement and the documentation — and say which one a claim comes from.

  2. 02

    Every number gets a source and a date. No date, no number.

  3. 03

    Label vendor-reported benchmarks at the claim. Not independent is not the same as wrong.

  4. 04

    Separate preprint from peer review, and name the venue and status.

  5. 05

    Print conflicting numbers side by side; never average them into a midpoint.

  6. 06

    Read the Chinese original for Chinese hardware and model releases; do not cite an English rewrite.

  7. 07

    Treat a promise as a promise: “weights by 4 November” is a date to check, not a shipment.

  8. 08

    Publish corrections with a date: the original claim, what was wrong, what changed, what is still open.
