公式与假设

URL 由协议、主机、端口、路径、查询串和片段组成。参数名和值必须单独编码，否则其中的 &、=、? 会被当成结构字符。

参数值编码

encodeURIComponent(值)：除 A–Z a–z 0–9 - _ . ! ~ * ' ( ) 外全部百分号编码

整条 URL 编码

encodeURI(URL)：保留 : / ? # [ ] @ ! $ & ' ( ) * + , ; = 等结构字符

查询串

查询串 = 参数名编码 + "=" + 参数值编码，用 & 连接

解码规则

%XX → 字节 → UTF-8；参数值解码时 + → 空格；非法 % 序列报错并给位置

假设与规则

  • 参数值请用参数值模式；整条 URL 模式会保留 ?、&、= 等结构字符，适合已经拼好的地址。
  • 解码参数值时 + 会被当作空格；如果 + 本身是数据，编码时应先写成 %2B。
  • 拆解保留重复参数与原始顺序，不做去重，也不自动解码路径和主机。
  • 相对地址、协议相对地址（//host/path）也能解析，协议或主机为空属于正常结果。

常见问题

encodeURI 和 encodeURIComponent 该用哪个？

处理整条 URL 用 encodeURI，它保留 : / ? & = 等结构字符；处理单个参数值用 encodeURIComponent，否则参数里的 & 和 = 会被误当成结构。

空格会变成 + 还是 %20？

encodeURIComponent 输出 %20；表单提交常把空格写成 +。解码时本工具会把 + 当作空格处理，若你的场景不是表单，请注意这一差异。

非法百分号会怎样？

例如 %ZZ 或末尾单独的 %，解码会报错并指出位置，而不是悄悄返回乱码。请先修正百分号编码再重试。
