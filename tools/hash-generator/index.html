公式与假设

哈希把任意长度的输入映射为固定长度的摘要，相同输入必然得到相同输出，无法从摘要反推原文。本页只做本地计算，不验证签名。

输入编码

字节 = UTF-8 编码(文本)；中文与 emoji 按 UTF-8 计数

摘要

摘要 = WebCrypto SHA(text)，输出长度由算法决定

输出长度

SHA-1 160 位 / SHA-256 256 位 / SHA-384 384 位 / SHA-512 512 位

比较方式

相同 = 去除空白并转小写后摘要完全一致

假设与规则

  • 哈希是单向摘要，不能还原原文，也不等同于加密或密码存储。
  • 换行符会参与计算：Windows 的 CRLF 与 Unix 的 LF 会得到不同结果。
  • SHA-1 仅用于兼容旧系统校验，不适合新的安全场景；安全场景优先 SHA-256 及以上。
  • 工具不验证数字签名，也不判断文件是否可信，只展示摘要。

常见问题

哈希和加密有什么区别？

哈希是单向摘要，不能还原原文；加密是可逆的，需要密钥。这里适合校验文件或文本是否被改动，不适合保存需要取回的密码。

为什么同样的文本每次结果都一样？

哈希函数是确定性的，相同输入必然得到相同输出。若结果不同，通常是多了空格、换行或编码不一致；页面会显示 UTF-8 字节数，可辅助排查。

比较两段文本时要注意什么？

比较的是哈希值是否相同，不是原文相似度。哪怕只差一个空格，结果也会完全不同；请确认两边使用同一算法和同一输出格式。
