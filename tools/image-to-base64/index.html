公式与假设

文件通过 FileReader 在浏览器里读成 data URI，再拆出 MIME 与 Base64 部分。预览、统计和复制都使用这份本地数据，页面没有网络请求，也不会把图片写入存储。

data URI 结构

data:<MIME>;base64,<数据>

MIME 取文件自身类型；缺失时按扩展名判断 jpg / png / webp。

体积估算

base64Length = 4 × ceil(bytes / 3)

Base64 约比原始文件大三分之一，另加 MIME 前缀。

  • 单文件固定限制 5MB；更大的图片请先用压缩或缩放工具处理。
  • 输入框在内容很长时只显示开头一段，三个复制按钮始终复制完整内容。
  • data URI 适合小图标与少量图片；浏览器无法单独缓存，也会让 HTML 体积明显变大。
  • 复制依赖浏览器剪贴板权限；在 file:// 下若失败会自动回退到选中文本并提示。
  • 扩展名与真实内容不符时，生成的 data URI 可能无法显示，请确认源文件没有改名错误。

常见问题

data URI 适合放进 HTML 吗？

适合小图标和少量图片。Base64 会让体积增大约三分之一，且无法被浏览器单独缓存；大图建议仍用文件 URL。

5MB 限制能改吗？

当前固定为 5MB，避免生成超长字符串导致页面卡顿或复制失败。更大的图片请先压缩或缩放，再转成 Base64。

MIME 类型是怎么判断的？

优先读取文件本身的类型，再结合扩展名。若扩展名与实际内容不符，data URI 可能无法显示，请确认源文件没有改名错误。以上处理全部在本地完成，不上传。
